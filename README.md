### Day 8 - 2/02/26
Today I focused on building small projects on my own and practicing problem-solving without relying on AI for solutions.

In my first number guessing game, I ran into a logic issue where the game stopped after one input. I realized this happened because I didn’t use a loop, so the program only asked for input once. I also initially placed the user input outside the loop, which prevented the game from continuing. Moving the input inside the loop fixed the issue and helped me better understand how program flow works.

In my second project, I expanded the game by:

- Adding a limit of 5 attempts

- Giving feedback based on how close the guess was to the correct number

- Showing a special message depending on how many attempts the player needed

One challenge I faced was placing the “special message” logic in the middle of the loop. This caused the message to print during every round instead of only after the game ended. Fixing this required me to rethink the structure of my code and move certain logic outside the loop. This helped me understand how important code order and structure are in programming.

Today was a strong exercise in debugging, structuring logic, and thinking more like a programmer rather than just writing code that “looks right.”


### Day 9 - 3/02/26

Today I focused on strengthening my core programming logic by building two small interactive Python programs: a password guessing game and a simple quiz.

Project 1 – Password Guessing Game

In this project, the player has five attempts to guess a secret password. After each incorrect guess, the program provides feedback such as:

Whether the guess is too short or too long

Whether the first letter is correct

If the password is guessed correctly, the program displays a success message along with the number of attempts used. If all attempts are used, the game ends and reveals the password.

What I practiced:

- Working with strings instead of numbers

- Comparing text input

- Structuring multiple conditional checks correctly

- Understanding how if vs elif affects program flow

Project 2 – Simple Quiz Game

This project asks the user three questions and keeps track of the score. After each answer, the program tells the user whether they were correct and updates the score. At the end, a final message is shown based on the total score.

What I practiced:

- Storing and updating a score variable

- Building programs with multiple stages (not just loops)

- Using conditionals to display different final outcomes

- Handling user input errors (preventing crashes when converting text to numbers)

Key Learning From Today

Today’s main focus was not just making programs work, but understanding why program structure and input validation matter. I learned that:

The order of conditions can completely change how a program behaves

Programs should be built to handle unexpected user input

Good structure makes debugging much easier
